社区插件索引随 dsh-web 家族对齐到统一版本 0.4.8。本版本收录两条社区插件条目，索引条目总数从 140 增至 142；索引数据源、包名、安装方式与 DSH 版本门槛均保持不变。

> **重要变更**：本版本没有重命名任何已持久化的标识符、线协议字段或 profile 格式，也没有需要手工迁移的改动。包名 `@linxin666/dsh-client-ui-community-plugins` 与安装方式不变；`community.json` 仍是工坊商店插件列表与 dsh-market.com 插件清单的唯一数据源。`dsh.engines.dsh` 与 `@deepseek-ai/dsh` peer 保持在 `>=0.2.1-rc.2`，bundle patch 里那行惰性 `ui-community-plugins` 行保持不变。

### 新功能

- 收录硬件监视 `dsh-vitals`：btop 风格的实时硬件监视，会话标题栏里一个 CPU / GPU 迷你小组件（点击打开完整视图），Chat / Trajectory 旁新增 Hardware 标签页，给出 CPU 总负载、60 秒走势与每核负载、内存、CPU 温度，以及每块 NVIDIA GPU 的温度、负载、功耗与显存（经 `nvidia-smi`）；每项信号取自系统提供的免特权数据源，没有就自动隐藏，零运行时依赖、无需配置。已在 Linux 上实测，macOS 与 Windows 的读取逻辑目前只用样例输出验证过
- 收录流式折叠 `dsh-streamfold`：在官方对话流上做展示增强，运行中自动展开最新的思考小窗、旧过程行折成一条摘要，一轮跑完把思考与工具调用折起而穿插正文保留；折叠按 3 行一组错峰、逐帧推进，不依赖历史是否加载完，折叠内容以 `hidden=until-found` 保持可搜索（Ctrl+F 仍能命中），跑完平滑回到你那一问。启用「折叠」档会接管官方「对话显示」设置：官方 transcriptView 停在 verbose 且那一行被隐藏；从本插件切回官方档会写回所选档，卸载后官方档停在「完全展开」，需要时到官方设置里改回

### 其他改动

- 版本从 0.4.7 对齐到 0.4.8：本包是单包仓库，`package.json` 的 `version` 是唯一的版本声明点；`dsh.engines.dsh`、`@deepseek-ai/dsh` peer、十一项 SDK devDependency 与 lockfile 均未移动

The community plugin index publishes on the family's aligned version 0.4.8. This release registers two community plugin entries, growing the index from 140 to 142 entries; the data source, the package name, the install path and the DSH version floor are unchanged.

> **Important change**: nothing persisted was renamed in this release - no identifier, wire-protocol field or profile format - and no manual migration is needed. The package name `@linxin666/dsh-client-ui-community-plugins` and its install path are unchanged, and `community.json` remains the single data source for the Workshop store plugin list and the dsh-market.com plugin manifest. `dsh.engines.dsh` and the `@deepseek-ai/dsh` peer stay at `>=0.2.1-rc.2`, and the inert `ui-community-plugins` row of the bundle patch is unchanged.

### New Features

- Register the hardware monitor `dsh-vitals`: a btop-style live monitor with a CPU / GPU mini widget in the session header (click opens the full view) and a Hardware tab next to Chat / Trajectory showing overall CPU load, a 60 s sparkline and per-core load, memory, CPU temperature, and per NVIDIA GPU temperature, load, power draw and VRAM (via `nvidia-smi`); each signal comes from an unprivileged OS source and hides itself when there is none, with zero runtime dependencies and no config. Tested live on Linux; the macOS and Windows readers are only checked against sample output so far
- Register the display enhancement `dsh-streamfold`: over the official transcript it opens the newest thinking window while a turn runs and folds older process rows into one summary, then folds thinking and tool calls away at the end of the turn while interleaved prose stays; folding staggers three rows at a time and advances per frame without waiting for history to load, folded rows stay searchable through `hidden=until-found` so Ctrl+F still finds them, and a finished turn scrolls back to your question. Its Fold mode takes over the official transcript display setting: the official transcriptView is parked on verbose and that row is hidden. Switching back to an official mode from this plugin writes the chosen mode back; uninstalling leaves the official value on Verbose until it is changed in the official settings

### Other Changes

- The version moves from 0.4.7 to 0.4.8: this is a single-package repository, so `version` in `package.json` is the only place the version is declared; `dsh.engines.dsh`, the `@deepseek-ai/dsh` peer, the eleven SDK devDependencies and the lockfile do not move
- Agent Notes: record the 2026-10-17 registration round, where twelve pull requests appended to the same `community.json` tail and only one could land per round; #33 (`dsh-vitals`) and #39 (`dsh-streamfold`) merged, three approved entries stayed blocked on a branch update and five were held on evidence. The same round states the uninstall behaviour of the `dsh-streamfold` entry accurately
- This package builds no client bundle: `src/` is unchanged since v0.4.7 and the rebuilt `lib/index.js` is still 5573 bytes; `lib/` is not committed and is produced by `pnpm build` in the release pipeline
